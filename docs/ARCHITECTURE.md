# Архитектура и правила

## Режимы AI

| `OPENAI_API_KEY` | Интервью | План |
|---|---|---|
| задан | модель формулирует следующий вопрос по непокрытым темам | модель выбирает услуги, приоритет и пишет объяснения |
| не задан или API недоступен | шаблонные вопросы, порядок зависит от главной заботы семьи и возраста | план по правилам (базовый набор + правила по ответам) |

Клиент использует `json_schema` в режиме strict. Если модель не принимает strict-схему, он один раз переключается
на JSON без схемы с проверкой через Pydantic; если не принимает `temperature`, параметр отключается. Тексты
интервью в логи не пишутся.

## Как соблюдаются жёсткие правила

- **Только справочник.** В JSON schema поле `service_id` — `enum` из справочника; код дополнительно отбрасывает
  чужие id, дубли и услуги не по возрасту и добавляет обязательный базовый набор. Куратор добавляет шаги только
  из справочника.
- **Без диагнозов, оценок, прогнозов и терапии.** Стоп-слова лежат в `backend/app/config.py`. Объяснение со
  стоп-словом или длиннее 300 символов заменяется шаблонным; вопрос интервью со стоп-словом — шаблонным вопросом.
- **Даты считает код.** `due_date = сегодня + default_deadline_days` (от приоритета не зависит), где «сегодня» —
  `demo_today` или реальная дата. Просрочка, `days_overdue` и эскалация (просрочка > `ESCALATION_AFTER_DAYS`)
  вычисляются при каждом чтении.
- **Регион.** Если услуги нет в городе семьи (`available_cities`), шаг остаётся в плане с блокером
  `no_service_in_region`.
- **Сбой модели.** Неверный JSON или ошибка API → один повтор → запасной план. Демо не ломается.
- **Родитель не видит черновик.** Пока статус не `confirmed`, `GET /api/cases/{id}` отдаёт родителю пустой `steps`.

## Роли

Вход без пароля, роль выбирается на входной странице (заголовок `X-Role`). Куратор видит все дела. Родитель видит
демо-кейсы и те, что создал или открыл сам (список хранится в браузере). Родитель меняет статус шага, отмечает
документы и ставит препятствие. Приоритет, заметки, правку состава плана, подтверждение, демо-дату и «Передачу дела»
делает только куратор.

## API

| Метод | Путь | Кто |
|---|---|---|
| GET | `/api/health`, `/api/services`, `/api/settings` | все |
| GET | `/api/cases` | куратор — все, родитель — демо-кейсы |
| POST | `/api/cases` `{child_alias, birth_date, city, language}` или `{scenario}` | все |
| GET | `/api/cases/{id}` | все (родитель без черновика) |
| POST | `/api/cases/{id}/interview/next` `{answer?}` → `{question, topic, options, done, progress}` | все |
| POST | `/api/cases/{id}/interview/autofill` — «Заполнить демо-ответами» | все, DEMO_MODE |
| POST | `/api/cases/{id}/plan/generate` `{force?}` → статус `awaiting_curator` | все; `force` — куратор |
| POST | `/api/cases/{id}/plan/confirm` | куратор |
| POST | `/api/cases/{id}/steps` `{service_id, priority}` / DELETE `/api/steps/{id}` | куратор |
| PATCH | `/api/steps/{id}` `{status?, priority?, blocker?, blocker_note?, curator_note?, documents?}` | куратор; родитель — без priority и curator_note |
| GET | `/api/curator/cases`, `/api/curator/overdue` | куратор |
| GET | `/api/cases/{id}/handoff`, POST `/api/cases/{id}/handoff/export`, GET `/api/cases/{id}/audit` | куратор, план подтверждён |
| POST | `/api/settings/demo-today` `{date \| null}` или `{shift_days}` | куратор, DEMO_MODE |
| POST | `/api/cases/{id}/reset`, `/api/demo/reset` | куратор, DEMO_MODE |

Отметка документа (`documents: [{name, have}]`) синхронизируется во всех шагах кейса. В `audit_log` пишутся
создание кейса, генерация и подтверждение плана, правка состава плана и экспорт «Передачи дела».
