## Проблема

Помощь ребёнку с расстройством аутистического спектра раздроблена между здравоохранением, образованием и
социальной защитой. Родители сами ищут, куда идти дальше, по нескольку раз собирают одни и те же документы и
пропускают сроки, а специалисты каждого ведомства видят только свой фрагмент маршрута. В итоге ребёнок позже
получает помощь, а после 18 лет сопровождение и вовсе обрывается.

## Решение

Веб-приложение с двумя ролями — родитель и куратор:

1. **Интервью.** Родитель отвечает на 8–12 вопросов в чате. AI подбирает следующий вопрос по ещё не покрытым темам
   (документы, текущая помощь, общение, обучение, быт, дорога, поддержка семьи, главная забота).
2. **Единый план.** AI выбирает шаги из справочника услуг трёх ведомств и объясняет каждый шаг простым языком. Код
   достраивает ответственного, срок, документы и статус.
3. **Подтверждение куратором.** Куратор правит и подтверждает план; семья видит его только после подтверждения.
4. **Контроль сроков.** Родитель и куратор ведут статусы, отмечают документы и препятствия. Просрочка и эскалация
   считаются автоматически, для эскалации готовится черновик уведомления руководителю ведомства.
5. **Передача дела.** Сводка по делу: выполнено, просрочено, документы, препятствия, ближайшие сроки, покрытие по
   областям помощи. Сохраняется в PDF.

Принципы: **диагнозов не ставим**, **шаги только из каталога услуг**, **сроки считает код, а не модель**,
**план подтверждает куратор**. Если модель недоступна, план собирается по правилам из базового набора услуг.

Подробности (роли, API, проверки) — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Демо

Сценарий (около 60 секунд):

1. **Родитель** → «Семья А» → 1–2 ответа → «Заполнить демо-ответами». Черновик плана уходит куратору.
2. **Куратор** → «Проверить план» → «Подтвердить план».
3. **Родитель** → «Мой маршрут»: шаги, сроки, документы; отметить шаг «В работе» или «Выполнен».
4. **Куратор** → дата демо «+10» → просрочки, эскалация и черновик уведомления.
5. **Куратор** → «Передача дела» → «Сохранить в PDF».

## Запуск

Требования: Python 3.14.3, Node.js 26.9.0 (npm 11.19.1), GNU Make. Docker не нужен.

```bash
make install   # venv для backend, npm ci для frontend, .env из .env.example
make run       # backend на :8000, frontend на http://localhost:3000
make test      # pytest (32 теста) + проверка типов TypeScript
```

Переменные окружения (файл `.env` в корне, значения не коммитятся):

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | ключ OpenAI; без него работает демо-режим без модели (шаблонные вопросы, план по правилам) |
| `OPENAI_MODEL` | модель, по умолчанию `gpt-6-luna` |
| `OPENAI_BASE_URL` | необязательно, свой endpoint OpenAI-совместимого API |
| `DB_PATH` | путь к SQLite относительно `backend/`, по умолчанию `./data/app.db` |
| `ESCALATION_AFTER_DAYS` | через сколько дней просрочки шаг эскалируется, по умолчанию `3` |
| `DEMO_MODE` | `true` включает кнопки даты демо, демо-ответов и сброса |
| `NEXT_PUBLIC_API_URL` | адрес API для браузера, по умолчанию `/api` (проксируется Next.js в FastAPI) |

Демо-режим: `DEMO_MODE=true`. Сброс данных — кнопка «Сбросить демо» на панели куратора или `make reset-db`
(база пересоздаётся из seed с двумя синтетическими кейсами при следующем запуске).

Проверка модели: `make eval` — 10 генераций плана на реальной модели. Результат на `gpt-6-luna` (30.09.2026):
10/10 валидный JSON по strict-схеме, 0 шагов вне справочника, 0 объяснений со стоп-словами.

## Структура проекта

```
backend/                 FastAPI + SQLite
  app/catalog.py         seed: справочник из 20 услуг, темы интервью, два синтетических кейса
  app/interview.py       адаптивное интервью (8–12 вопросов)
  app/plan.py            генерация плана, валидация и достройка шагов кодом
  app/tracking.py        просрочки, эскалация, препятствия, черновик уведомления
  app/handoff.py         «Передача дела»
  app/llm.py             клиент OpenAI (structured outputs, запасной JSON-режим)
  app/safety.py          проверка стоп-слов (список в app/config.py)
  app/main.py            REST API
  tests/                 pytest
  scripts/eval_plan.py   проверка генерации на реальной модели
frontend/                Next.js (TypeScript)
  app/                   экраны: вход, кабинет и маршрут родителя, чат-интервью, панель и дело куратора, передача дела
  app/api/[...path]/     прокси /api → FastAPI
  components/, lib/      карточка шага, бейджи, типы, клиент API
docs/                    архитектура и скриншоты
Makefile, dev.sh         установка, запуск, тесты
```

- [x] Роли родитель и куратор без паролей, выбор на входной странице
- [x] Создание кейса (условное имя, дата рождения, город, язык) и два синтетических кейса
- [x] Адаптивное чат-интервью на 8–12 вопросов с прогрессом и кнопкой «Заполнить демо-ответами»
- [x] Генерация плана через OpenAI structured outputs; шаги только из справочника, проверка возраста и стоп-слов
- [x] Запасной план при недоступности модели или невалидном ответе
- [x] Подтверждение и правка плана куратором (приоритет, удалить или добавить шаг из справочника)
- [x] Родитель не видит план до подтверждения
- [x] Статусы, документы (есть/нет), препятствия, заметки куратора; журнал действий
- [x] Просрочка, эскалация и черновик уведомления; дата демо (+1 / +7 / +10 / +14, сброс)
- [x] «Передача дела» с сохранением в PDF, доступна только куратору
- [x] 32 автотеста
- [ ] Публичная HTTPS-ссылка (разворачивается на сервере)
- [ ] Точки перехода по возрасту, «паспорт ребёнка», объяснения на казахском (P2)

Ограничения: данные только синтетические; справочник услуг неполный и составлен командой, его нужно сверить с
реальным перечнем; нет интеграции с chis.kz и ПМПК; уведомления руководителям ведомств не отправляются (только
черновик); авторизации нет — это демо.
